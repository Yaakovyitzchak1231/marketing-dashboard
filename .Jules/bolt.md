## 2024-05-18 - Avoid Next.js un-deduped fetch for concurrent renders

**Learning:** `loadShellData` was fetching the `/api/overview` and `/api/campaigns` multiple times in a single server render pass (once for `loadShellData(null)` and then again in `loadShellData(firstCampaignId)` if there were campaigns). Next.js's standard `fetch` dedupes requests on the same route with identical options, but since `loadShellData` uses a custom `getJson` and constructs its own `fetch`, in some situations or with custom wrappers, it might fail to cleanly dedupe, or it's just much cleaner to rely on `React.cache()` for deterministic request deduping. By moving the discrete fetch calls for overview, campaigns, and trend into dedicated `React.cache()` wrapped functions, we guarantee that multiple invocations of `loadShellData` within the same server render pass will instantly return the cached promise, cutting redundant round trips in half! This is a massive optimization for page load latency since it removes synchronous waterfall network latency for duplicated fetches.
**Action:** When data loaders are called multiple times in a single RSC render pass, ensure the internal fetching blocks are explicitly wrapped in `React.cache` to guarantee no duplicate network requests are made.

## 2024-05-18 - Reduce Garbage Collection Overhead in API Route Data Aggregation
**Learning:** In API routes that aggregate large datasets (like `app/api/funnel/route.ts`), chaining array methods such as `rows.map(r => r.value)` before passing the result to a `sum()` function creates a new intermediate array for every metric column and for every campaign/idea group. This leads to heavy object allocation and subsequent garbage collection churn, slowing down request processing time, especially for accounts with extensive history.
**Action:** Replace `sum(rows.map(r => r.key))` with a purpose-built `sumCol(rows, 'key')` function that iterates directly over the original array of objects and retrieves the property. This avoids allocating any temporary arrays and significantly reduces memory overhead and GC pressure.

## 2024-10-05 - Optimize intermediate array allocations via flatMap and map chaining
**Learning:** Chaining array methods like `flatMap()` followed by nested loops mapping logic can lead to unnecessary allocations and memory overhead, especially in Node.js/Next.js API routes when iterating large arrays (like joining database results).
**Action:** When computing aggregates or sums on nested items within mapping functions, write inline `for...of` loops rather than allocating intermediate mapping arrays (like `flatMap`). This speeds up runtime logic heavily while helping memory usage.

## 2024-11-20 - Process paginated database fetch loops inline rather than buffering arrays
**Learning:** When pulling large datasets using `.range()` in loops, pushing all pages into a massive intermediate array (`all.push(...data)`) before processing them requires peak memory to spike severely before aggregating them down into a map of small objects. This causes heavy heap allocation for no reason.
**Action:** In API endpoints using paginated fetches, move the aggregation or processing loop *inside* the fetch loop to process chunk by chunk. Once a chunk is aggregated, it can be garbage collected without ever needing `all.push(...data)`.
